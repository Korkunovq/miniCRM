# Как устроена мини-CRM (для руководителя)

## Зачем система

Руководитель (постановщик) ведёт **объекты** — это стройки с названием и адресом. На каждый объект ставятся **задачи**: что сделать, кому поручено, в каком состоянии работа. Исполнитель видит только **свои** задачи и может переводить их по понятным шагам: взять в работу → сдать на проверку → при необходимости снова в работу после замечаний. Постановщик принимает работу или возвращает на доработку с обязательным комментарием.

## Как это выглядит в работе

1. Все входят по **email и паролю**. Новых пользователей заводит администратор — самостоятельная регистрация отключена.
2. Постановщик создаёт объекты и задачи, назначает исполнителя.
3. Исполнитель в «Мои задачи» или в карточке объекта открывает задачу и нажимает только те кнопки, которые разрешены сейчас (например, нельзя «принять» задачу исполнителю — это делает постановщик).
4. В карточке задачи видна **история**: кто, когда и как менял статус, с комментарием при возврате на доработку.

## Как защищены данные

Данные лежат в облачной базе **Supabase**. Это не «скрытые кнопки в интерфейсе», а **правила в самой базе** (Row Level Security):

- Исполнитель **не может прочитать** чужую задачу, даже если попытаться обратиться к базе напрямую, минуя наш сайт.
- **Нельзя прыгнуть** в любой статус: база проверяет каждый переход (например, «Принята» только у постановщика из статуса «На проверке»).
- **Историю статусов нельзя подделать или стереть** через обычный доступ приложения — записи создаёт только проверенная процедура при смене статуса.
- На сайт попадает только **публичный ключ** для клиентского приложения; секретный ключ администратора в код не кладётся.

## Что исполнитель не может сделать

- Смотреть или менять задачи других людей.
- Создавать, удалять объекты и задачи.
- Принимать задачу или возвращать на доработку (это постановщик).
- Обойти порядок статусов (например, сразу закрыть задачу как «Принята»).

Постановщик видит все объекты и задачи и управляет ими в рамках правил статусов.
