# Решения и допущения

## Роли и пользователи

- Роли хранятся в таблице `profiles`, связанной с `auth.users`. Первых пользователей и профили создаём вручную в Supabase (как в ТЗ).
- Открытая регистрация в UI не реализована; в Supabase рекомендуется отключить email signup.

## Объекты и задачи

- Таблица объектов названа `construction_objects`, чтобы не конфликтовать с зарезервированным словом `objects`.
- При создании задачи статус всегда `new`; первая запись в истории создаётся триггером (`— → Новая`).
- Постановщик может редактировать поля задачи (название, описание, исполнитель) без смены статуса; смена статуса только через RPC.

## Статусы

- Переходы реализованы в функции `transition_task_status` (SECURITY DEFINER) + триггер запрещает менять `status` напрямую в `UPDATE`.
- Комментарий обязателен только при переходе «На проверке → На доработке».

## UI

- Ant Design — быстрый аккуратный интерфейс, локаль `ru_RU`.
- Исполнитель видит пункт меню «Мои задачи»; постановщик — полный доступ к объектам и задачам.

## Не успел / можно улучшить при большем времени

- E2E-тесты (Playwright) на RLS и переходы статусов.
- Realtime-подписки Supabase для обновления списков без перезагрузки.
- CLI Supabase (`supabase db push`) вместо ручного SQL в редакторе.
- Seed-скрипт с автоматическим созданием пользователей через Admin API (требует service_role на CI, не в репозитории).
